### 4.23 改派侧不变量（109-112，2026-11-11 补充）

改派侧的门禁单独住在 `v_invariant_checks_reassign` 里。

| # | 不变量 |
|---|---|
| 109 | 改派留痕的最后一跳必须等于明细当前值（明细不许在改派之后被人手改过） |
| 110 | 改派留痕的链必须自洽，且第一跳从下单时的定价快照起（链断了 = 有一次改派没留痕） |
| 111 | 已收款的订单不许有改派过的明细（已成交的金额不许因为换源而失去依据） |
| 112 | 单张形态的成分行必须与明细的采纳源一致（两处说的不是同一个源 = 按 A 源的价格卖、按 B 源出票） |

- 留痕断了（不变量 110）—— 链上第一跳必须从下单时的定价快照起，
  每一跳的「到」必须是下一跳的「从」。断了就是有事实被洗掉。
- 明细被手改了（不变量 109）—— 改了价、改了源，留痕不认：
  留痕是改派这件事唯一的记录，人手改库绕过了它。
- 已收款的订单被改派（不变量 111）—— 已成交的金额失去依据，
  差价退不退是业务决策，不是改派能顺手做的。
- 成分行与明细分叉（不变量 112）—— 履约按成分行建预订。
  改了明细不挪成分行 =「按 A 源的价格卖、按 B 源出票」。

不变量 54 也随之修订：改派过的行，单价等于**改派留痕里的新单价**；
没改派过的行，单价仍等于下单时的定价快照。下单时的定价快照是**冻结**的 ——
它记的是「当时报给客户的那个价」，改派不改写历史，改派写自己的留痕。

口径在 §5.20。

### 4.24 源侧售卖份数区间侧不变量（113-115，2026-11-11 补充）

源价行上的 `min_qty` / `max_qty` 是源侧的一手事实（最少成团人数 / 单笔上限）。
这一对整数以前全库没有一处读它 —— 客户买 1 张按团价的票，
系统按整团价收了 1200，源侧因为不足 6 人拒单：钱收了、票出不来。

份数区间侧的门禁住在 `v_invariant_checks_qty_limits` 里。

| # | 不变量 |
|---|---|
| 113 | 明细留痕的份数必须落在留痕的区间内（留痕自相矛盾 = 当时的区间不是这样） |
| 114 | 区间留痕必须指向明细的采纳源（留痕说的是别的源 = 对账对不上） |
| 115 | 改派过的明细必须记着当前采纳源的区间（换源之后区间没跟着换 = 拿着旧源的区间付新源的钱） |

- 留痕自相矛盾（不变量 113）—— 留痕记的是「当时源侧接不接得住这一单」，
  份数落在区间外 = 这笔单当时就接不住，却收了钱。
- 留痕指向别的源（不变量 114）—— 区间是**那个源**的约束，
  记在别的源头上 = 对账时按错的对象核。
- 改派后区间没换（不变量 115）—— 改派换了源，新源的区间是新的事实，
  留着旧源的区间 = 用旧源的承诺付新源的钱。
  这条按迁移账本里的 `applied_at` 卡时间：规则之前发生的改派本来就没有区间留痕，
  那不是违规，是规则还没存在。

口径在 §5.21。

### 4.25 按团报价单位价口径侧不变量（116-118，2026-11-11 补充）

按团报价的源价行给的是**团总价 / 团成本**（整团 1200 / 1100），
明细里记的单位价与单位成本是**分摊到人**的（171.43 / 157.14）。
分摊口径只有一个实现：`fn_unit_amount(basis, total, quantity)`。

门禁住在 `v_invariant_checks_reassign_basis` 里。

| # | 不变量 |
|---|---|
| 116 | 按团报价的明细：单位价格必须等于团总价分摊到人 |
| 117 | 按团报价的明细：单位成本必须等于团成本分摊到人 |
| 118 | 待改派清单说「成本变了」的按团明细：按人均口径算也必须真的变了 |

- 单位价没分摊（不变量 116）—— 拿团总价当单价，收的钱是团价，出票按人头数。
- 单位成本没分摊（不变量 117）—— 成本记的是团成本，而明细记的是人均，
  两处说的不是同一个数，对账时成本对不上。
- 清单与写路径不同口径（不变量 118）—— 待改派清单比成本时拿团成本比人均成本，
  每一条按团明细都被说成「成本变了」，而写路径自己会返回 `no_change`。
  运营被告知一条没变的明细要改派 —— 清单说的与写路径做的不一样，
  清单就不可信。这条守着清单：口径没修好时它当场报警。

口径在 §5.22。

### 5.20 改派的口径（2026-11-11 落地）

**改派是什么**：一条明细在**下单之后、支付之前**跟当前的世界对不上了 ——
源侧把那个 SKU 下架了、源场次取消了、报价变了、或者出现了更便宜的源。
这时明细还钉在原来的源和原来的价上：按旧价卖出去的东西，
要么出不了票，要么按一个已经过期的价卖（选源与定价必须同源，硬约束 15）。

唯一实现：`fn_reassign_order_item(order_id, order_item_id, reason)`
（`db/migrations/024_reassign_order_item.sql`）。
Go 侧是 `internal/reassign`（只拼参数、只读结果，不重排源、不重算钱），
CLI 是 `tc-connect order reassign` 与 `tc-connect order stale`。

七条口径写死：

- **改派是重新选源 + 重新定价。** 源与价都取自 `fn_price_variant()` ——
  它既选源又定价。Go 侧不另排一次序、不另算一次钱。
- **只发生在未收款的时候。** 已收款的订单切换采纳源，
  已成交的金额就失去依据了 ——
  差价退不退、怎么收，是业务决策（行级退款还没落地），不是这里能编的规则。
  已收款 = 不改派，让它走退款流程。
- **只对单张形态。** 配方与套装的源是**声明**的
  （源侧那个配方 / 源侧那个整套 SKU），不是选出来的；
  它们的换源是重新声明，不是改派。
  判定用 `product_variant.variant_role` —— 下单与定价这两条路也是用它分的。
- **只对还没预订过的明细。** 预订是事实：
  已经发到源侧的预订不能靠换源把它抹掉（不变量 58）。
- **成分行跟着明细一起走。** `sales_order_item_source` 那一行才是履约
  真正用的源（建预订按它建，不变量 58 也按它判）。
  改了明细不挪这一行 =「按 A 源的价格卖、按 B 源出票」。
- **库存预占跟着源走。** 预占记的是「我们承诺了多少」：
  钉在旧源上 = 旧池子继续被占着、新池子没被占
  ——「按新源卖、按旧源占库存」（硬约束 22）。
  挪之前先查新源的池子：明知不够当场报错（超卖比少卖更贵）。
- **留痕。** 改派把「从哪个源、哪个价，换到哪个源、哪个价」
  写进明细快照的 `reassignments` 数组（018 的那条纪律：
  事实不许被一次调用洗掉）。下单时的定价快照是冻结的，不许跟着改。

读侧给一个视图 `v_reassign_candidates`：哪些明细跟当前的选源与定价对不上了，
并说清差在哪（源变了 / 价变了 / 成本变了 / 当天没有可用报价）。

幂等：重复调用同一个改派不会改第二次（幂等键就是「这一条明细 + 当前的世界」），
返回 `outcome='no_change'`，留痕不追加。

表与函数：

| 位置 | 干什么 |
|---|---|
| `fn_reassign_order_item` | 唯一实现：改派一条明细（重新选源 + 重新定价） |
| `v_reassign_candidates` | 读侧：哪些明细跟当前世界对不上、差在哪 |
| `v_invariant_checks_reassign` | 改派侧不变量（109-112） |

### 5.21 源侧的售卖份数区间口径（2026-11-11 落地）

**这件事是什么**：`supplier_price_calendar` 上有一对整数 `min_qty` / `max_qty`。
它说的是「这份报价能接的最小 / 最大份数」：
`min_qty > 1` 是最少成团人数（携程 `priceSettingType = 4` 的「最少 6 人成团」），
`max_qty` 是单笔上限。种子里已经填了，但全库没有一处读它 —— 这条事实一直是死的。

**为什么非读不可**：按团报价的源价行是「整团 1200，最少 6 人」。
客户只买 1 张 → 系统按整团价收了 1200 → 源侧因为不足 6 人直接拒单。
钱收了、票出不来，这是「收了钱出不了票」最典型的形态。

唯一实现：`fn_source_quantity_limits()`（读源价行上的那一对整数）
与 `fn_qty_servable()`（判这个源接不接得住这个份数）。
写路径、留痕、不变量都走它们，别处不再写一遍比较。

七条口径写死：

- **区间是源侧的一手事实，唯一读法是 `fn_source_quantity_limits`。**
  它按「源变体 × 规范变体 × 日期」读源价行 —— 这把键与选源函数
  （`fn_route_candidates`）连源价行时用的是同一把，
  所以读到的一定是定价时看到的那一行。读不到 = 源侧没给约束 = 不拦（不猜）。
- **份数的单位 = 源侧的售卖单位**，也就是我们发给源侧的那条预订里的份数：
  单张·按人 = 份（票），单张·按团 = 人（团人数），套装 = 套，
  配方 = 该源 SKU 的份数。
- **同一个源 SKU 顶多个成分时，比的是这个 SKU 的总份数。**
  参数化源里成人与儿童是同一个 SKU，源侧收到的是**一条预订里的总份数**
  （2 份成人 + 1 份儿童 = 3 份）。按成分各判各的会漏掉「合起来超上限」：
  每份单独看都合法，合起来超过源侧的单笔上限，源侧照样拒单。
- **落单时必须落在采纳源的区间内，否则当场报错说清差在哪**
  （源、日期、区间、这一单的份数）。不拦下来就是收了钱出不了票。
- **按团报价的团总价只在人数达标时成立** —— 1 个人不能按团价成交。
  报错里的份数是人数，不是「一整团」。
- **我们不按份数换源。** 换了源就是另一个价，而售价行没有份数维度；
  要按份数换源，得给价格加阶梯（另一个增量）。这次只做「如实拦住 + 说清」。
- **改派也要守这条**：新源接不住这一单的份数 → 拒绝改派
  （不许改成一个出不了票的源）。改派后的区间留痕跟着新源换。

区间记进明细快照的 `quantity_limits`：事后对账时能看出当时源侧接不接得住
（源侧后来改了他的成团人数，我们这边记的是当时那一版）。

表与函数：

| 位置 | 干什么 |
|---|---|
| `fn_source_quantity_limits` | 唯一读法：这个源在这些规范变体、这一天能接的份数区间 |
| `fn_qty_servable` | 唯一判定：这个源接不接得住这个份数 |
| `fn_place_order` | 落单前的区间校验（按明细逐项判，份数与源 SKU 归拢） |
| `fn_reassign_order_item` | 改派前的区间校验（新源接不住就不改派） |
| `v_invariant_checks_qty_limits` | 份数区间侧不变量（113-115） |

### 5.22 按团报价的单位价口径（2026-11-11 落地）

**这件事是什么**：按团报价的源价行给的是**团总价 / 团成本**
（整团 1200 / 团成本 1100），而订单明细里记的单位价与单位成本是
**分摊到人**的（171.43 / 157.14）。这是两种数，混起来比就是错的。

**错在哪**：待改派清单 `v_reassign_candidates` 比售价时做了分摊
（`round(sell_price / quantity, 2)`），比成本时却直接拿团成本和人均成本比 ——
1100 ≠ 157.14，于是每一条按团报价的未收款明细都被说成「成本变了」。
写路径（`fn_reassign_order_item`）的分摊一直是对的，所以真去改派，
函数自己会返回 `no_change`：清单说的与写路径做的不一样，清单就不可信。

唯一实现：`fn_unit_amount(basis, total, quantity)` ——
按团报价按人分摊（保留两位小数），按人计价原样返回。
写路径与读路径都调它，不各写一遍 CASE。

四条口径写死：

- **总价 → 单位价只有一个实现。** `fn_unit_amount` 是它唯一的位置。
  下单（`fn_place_order`）、改派（`fn_reassign_order_item`）、
  待改派清单（`v_reassign_candidates`）都调它。
- **按团报价的人均只是分摊，不是价。** 团总价与人数不成正比，
  人均那一份不许拿去和按人计价的单价比。
- **明细里记的是分摊后的数。** 明细的单位价 / 单位成本都是分摊到人的，
  团总价与团成本留在快照里（`detail_snapshot->'group_total'` /
  `->'cost_price'`）—— 对账时看的是当时的团价，不是今天的。
- **清单与写路径必须同口径。** 清单说「成本变了」，
  按人均口径算也必须真的变了（不变量 118）。

表与函数：

| 位置 | 干什么 |
|---|---|
| `fn_unit_amount` | 唯一实现：总价 → 单位价（按团按人分摊，按人原样） |
| `fn_place_order` | 写路径：落单时用 `fn_unit_amount` 记单位价与单位成本 |
| `fn_reassign_order_item` | 写路径：改派时用同一口径算新单位价与新单位成本 |
| `v_reassign_candidates` | 读路径：待改派清单，成本与价格的比较都用同一口径 |
| `v_invariant_checks_reassign_basis` | 按团单位价口径侧不变量（116-118） |
